# DemoBet88 Demo Bot + 管理后台 部署指南

一个服务同时跑两样东西：**Telegram Bot** 和 **管理后台网页**。后台里改的菜单按钮、欢迎页、FAQ、活动、公告排程、素材，bot 立即同步，不需要重新部署。

## 账号与权限
- 每个品牌是一套独立部署（一个 bot、一个后台）。
- 系统账号 **owner**：密码来自变量 `ADMIN_PASSWORD`，是技术支持的恢复入口，不能被停用或删除。
- 品牌方的员工账号由超级管理员在后台「员工与权限」开设，只有两种角色：
  - **超级管理员**：全部功能，包括员工、机器人设置、发布位置、操作记录
  - **管理员**：总览、发文排程、素材库
- 操作记录会写明是谁做的。停用账号会立刻把对方登出。

## 后台功能
| 页面 | 功能 |
|---|---|
| 工作总览 | 新增用户、绑定Giftcode、签到人数、互动人数（bot 实际记录），7/30 天趋势图，待办提醒 |
| 发文排程 | 一个窗口完成：选发布位置、写正文、拖入图片/视频（自动存入素材库）、选「立即发送 / 定时发送 / 存为草稿」，含 Telegram 预览、复制、发给自己看看 |
| 素材库 | 上传图片/视频，自动转成 Telegram file_id。**保留 30 天后自动清理**（被排程、草稿、机器人设置使用中的不会清理，也可手动延长）。文件本体存在 Telegram，不占服务器硬盘 |
| 机器人设置 | 菜单按钮、欢迎页、FAQ、限时活动、**发布位置**（设置常用群组/频道并「测试连接」） |
| 员工与权限 | 开设/停用员工账号，两种角色（仅超级管理员） |
| 操作记录 | 后台每次修改的记录 |

## 部署步骤
1. **GitHub**：新建 Private repo，上传 `bot.js`、`admin.js`、`store.js`、`package.json`、`public/index.html`、`.gitignore`、`.env.example`（注意 `public` 文件夹要一起传）。
2. **Railway**：New Project → Deploy from GitHub repo。
3. **Variables**（用 Raw Editor 一次贴）：
   ```
   BOT_TOKEN=你的Token
   ADMIN_PASSWORD=你自己设的密码
   STORAGE_CHAT_ID=（先留空，见下一步）
   DATA_DIR=/data
   ```
4. **挂 Volume**：Railway 服务 → Settings → Volumes → Mount path 填 `/data`。**正式客户一定要挂**：员工账号、发布位置、素材记录、公告都存在这里，没挂的话重新部署后会全部重置（只适合临时演示）。
5. **取得 STORAGE_CHAT_ID**：部署成功后，私聊 bot 发 `/chatid`，把回覆的 Chat ID 填进 `STORAGE_CHAT_ID`，让服务重启。
6. **开启后台网址**：服务 → Settings → Networking → Generate Domain（或绑自己的域名，例如 `desk.mjhco.com`，在域名 DNS 加 CNAME 指向 Railway 给的地址）。用 `ADMIN_PASSWORD` 登入。

⚠️ Railway 若出现变量读不到值，直接换一个新的变量名重新加。启动 log 会印出 `[环境变量检查]`，显示「（未设置）」就是没读到。

## 给品牌方交付的步骤
1. 用 owner 登入后台，到「机器人设置 › 发布位置」添加他们的群组/频道，点「测试连接」确认 bot 能发
2. 到「员工与权限」为品牌老板开一个**超级管理员**账号，再让老板自己开他的员工（**管理员**）
3. 把后台网址和账号交给对方。之后他们日常只需要「发文排程」和「素材库」

## 怎么发布一则公告
1. 「发文排程」→ 新建公告
2. 选发布到哪里（下拉选名称）→ 写正文 → 点选或拖入图片/视频（自动存入素材库）
3. 选发送方式：「立即发送」马上发；「定时发送」选时间（有「1小时后 / 今晚8点 / 明早9点」快捷键）；「存为草稿」先不发
4. 想先看效果：点「发给我自己看看」（需要已设置 STORAGE_CHAT_ID）

## 现场展示建议
1. 手机打开 bot 走一遍用户端（签到、抽奖、邀请、活动）
2. 打开后台，在「机器人设置」改一个按钮文字或 FAQ，保存
3. 回手机再点，立刻看到变化（这是最有说服力的一幕）
4. 后台新建一则公告排在 1 分钟后，现场看它自动发出
5. bot 里点「内部功能展示 → 今日发文」，读到的就是后台刚排的公告

## 注意事项
- 会员资料（积分、签到、推荐）仍在记忆体，重启会清空；后台配置与素材记录存在 `DATA_DIR`
- 一个服务只对应一个品牌（一个 bot）；多品牌就是多套部署，每套有各自的 owner 与员工账号
- 没有「忘记密码」邮件功能：员工忘记密码由超级管理员在「员工与权限」重设；超级管理员忘记则由技术支持改 `ADMIN_PASSWORD`（owner）后重设
- file_id 只对当前这个 bot 有效，换 bot 要重新上传素材
- 图片上限 10MB，视频上限 50MB（Telegram Bot API 限制）
- 邀请链接会真实归因：好友通过 `?start=ref_xxx` 首次进入即算一笔，推荐人收到通知
- 本 demo 不接真实平台 API，不做风控异常标记
